\begin{frame}{Proposed Contributions}
  \begin{alertblock}{Our contribution}
    Run 30 validates the source-ray correction idea with true RGB-D source
    depth. The current target setting keeps MV-DUSt3R+ as the candidate
    generator and replaces true source depth with depth estimated from RGB by
    the Run 37 fine-tuned depth model.
  \end{alertblock}

  \vspace{0.12cm}
  \begin{itemize}
    \item \textbf{Strong RGB-only baseline:} Run 11 improves B0 across 2--5
    views using view selection and fixed confidence thresholds.
    \item \textbf{Negative RGB-only analysis:} Runs 22--29 show that proxy F1,
    candidate filtering, and generic monodepth do not solve reconstruction.
    \item \textbf{Validated RGB-D reference:} Run 30 uses input source depth
    maps with poses/intrinsics for source-ray correction and passes all gates.
    \item \textbf{Estimated-depth target:} Run 37 fine-tunes the RGB depth
    estimator; the next correction setting should use that estimated depth to
    align MV-DUSt3R+ candidates.
  \end{itemize}
\end{frame}

\begin{frame}{Predicted-Depth Generalization Track}
  \footnotesize
  \begin{block}{Goal}
    Move from true RGB-D source depth toward RGB image input by estimating
    source depth from RGB, then using that depth for candidate correction.
  \end{block}

  \begin{itemize}
    \item Run 35: evaluate Depth Anything V2 Metric Indoor Small using AbsRel,
    RMSE, MAE, \(\delta_1/\delta_2/\delta_3\), and scale-aligned errors.
    \item Run 36: first predicted-depth correction attempt with the generic
    depth model; it did not pass reconstruction gates.
    \item Run 37: fine-tune the depth estimator so the next correction run can
    use a stronger estimated-depth anchor.
    \item True source depth is forbidden from Run 36 correction and residual
    gating; it remains evaluator/proxy-GT data only.
  \end{itemize}

  \begin{alertblock}{Claim boundary}
    The target setting is RGB-only for source depth, but it is not fully
    pose-free and is not the MV-DUSt3R+ paper benchmark setting.
  \end{alertblock}
\end{frame}

\begin{frame}{Contribution Details}

  \begin{block}{1. Baseline that solves sparse-view instability}

      \item This solves the first limit but leaves occlusion and wrong-depth

    \end{itemize}

    \begin{itemize}
      \item OARH, RSDH, RAJAH, and monodepth corrections are tested through

      \item They expose why filtering hurts recall/completeness and why

  \end{block}

  \begin{block}{3. Run 30 source-depth correction}
    \begin{itemize}
      \item Uses source RGB-D depth maps with known camera poses/intrinsics.
      \item Corrects source rays in metric geometry instead of deleting

    \end{itemize}
  \end{block}
\end{frame}

\begin{frame}{Why RGB-only Failed}
  \footnotesize
  \begin{block}{Transition narrative}
    Runs 22--29 showed that RGB-only filtering/correction was insufficient. Run
    30 changes the inference contract to RGB-D and passes the overall,
    occlusion, and ambiguity gates.
  \end{block}

  \begin{itemize}
    \item Proxy F1 did not transfer to reconstruction-level F-score.
    \item Filtering removed valid sparse-view geometry and hurt recall.
    \item All-candidate retention became a strong non-learned baseline.
    \item RGB-only monodepth did not recover metric/source depth well enough.
  \end{itemize}
\end{frame}
