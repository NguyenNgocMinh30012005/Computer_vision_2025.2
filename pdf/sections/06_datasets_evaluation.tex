\begin{frame}{Normalized Geometry Metrics}
  \small
  For each point cloud, remove translation and isotropic RMS scale:
  \[
    \hat X =
    \frac{X-\bar X}
    {\sqrt{\frac{1}{|X|}\sum_{x\in X}\|x-\bar X\|_2^2}}.
  \]

  \begin{columns}[T]
    \column{0.49\textwidth}
    \begin{block}{Normalized distance}
      \[
        \mathrm{ND}_{sym} =
        \tfrac{1}{2}\bigl(
        \operatorname{mean}d(\hat P,\hat G)+
        \operatorname{mean}d(\hat G,\hat P)\bigr)
      \]
      Lower is better; measures two-way normalized shape error.
    \end{block}

    \column{0.49\textwidth}
    \begin{block}{DAc@0.2 normalized}
      \[
        \frac{|\{p\in\hat P:d(p,\hat G)\leq0.2\}|}{|P|}
      \]
      Higher is better; measures prediction-side normalized accuracy.
    \end{block}
  \end{columns}

  \begin{alertblock}{Scope}
    Auxiliary paper-style metrics only. They still use depth-derived proxy GT,
    and normalization does not remove rotation.
  \end{alertblock}
\end{frame}

\begin{frame}{Why RGB-D Works}
  \footnotesize
  \begin{alertblock}{Final wording}
    RGB-only learned extensions did not pass reconstruction-level gates. After
    switching the inference contract to RGB-D, Run 30 uses input source depth
    maps with known camera poses/intrinsics for source-ray correction and passes
    the overall, occlusion, and ambiguity gates on held-out scenes.
  \end{alertblock}

  \begin{itemize}
    \item Source depth anchors each source ray to metric geometry.
    \item Correction preserves candidate count, unlike filtering that hurts
    recall and completeness.
    \item Occlusion and repeated/wrong-depth cases improve because the method
    fixes geometry rather than discarding sparse-view evidence.
  \end{itemize}
\end{frame}

\begin{frame}{Run 37 To Estimated-Depth Correction}
  \footnotesize
  \begin{block}{Why Run 37 exists}
    Run 36 showed that generic predicted depth was not accurate enough for
    source-ray correction. Run 37 fine-tunes the depth estimator on the
    available RGB-D frame pool so predicted depth can become a stronger
    correction anchor.
  \end{block}

  \begin{itemize}
    \item Input at reconstruction time: sparse RGB views plus known camera
    poses/intrinsics.
    \item MV-DUSt3R+ still produces the candidate point cloud.
    \item The fine-tuned depth model estimates per-view source depth from RGB.
    \item Estimated depth is back-projected and used for Run 30-style
    source-ray correction.
  \end{itemize}

  \begin{alertblock}{Evaluation rule}
    This is a target setting, not a completed claim. It must be evaluated
    against MV-DUSt3R+ RGB-only, generic predicted-depth correction, and the
    Run 30 true-depth reference.
  \end{alertblock}
\end{frame}
