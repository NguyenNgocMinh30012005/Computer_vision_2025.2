# Supervised Extension Report Section

## Motivation

The first experiment phase shows that view selection and confidence calibration are the most reliable improvements over the MV-DUSt3R+ baseline. In contrast, the hand-written fusion, occlusion filtering, and ambiguity filtering rules reduce F-score on the current proxy benchmark. This suggests that severe occlusion and repeated structures should not be handled by manually designed penalties alone.

We therefore propose a second-stage learned extension:

```text
Supervised Occlusion- and Ambiguity-Aware Sparse-View Reconstruction
```

The key idea is to keep the pretrained MV-DUSt3R+ backbone fixed at first, use it to generate candidate pointmaps and confidence scores, and train lightweight supervised heads that learn point reliability, visibility, and match validity from geometry labels.

## Proposed Pipeline

```text
Selected sparse views
-> MV-DUSt3R+ pretrained
-> candidate point cloud + confidence + pointmaps
-> Occlusion-Aware Reliability Head
-> MASt3R reciprocal matches
-> Repeated-Structure Disambiguation Head
-> learned filtering / fusion
-> refined point cloud
```

The winning components from the first phase are preserved:

- best sparse-view selection policy;
- fixed confidence threshold selected on validation;
- F0 baseline fusion as the fallback geometry aggregation.

The failed heuristic modules are replaced by supervised modules rather than manually tuned again.

## Occlusion-Aware Reliability Head

The occlusion module is formulated as a point reliability prediction problem. For each candidate point `p` predicted by MV-DUSt3R+, the head predicts:

```text
r(p) in [0, 1]
```

where `r(p)` is the probability that the point should be retained.

Candidate features include:

- MV-DUSt3R+ confidence;
- visible-view count;
- occluded-view count;
- reprojection error;
- depth disagreement;
- baseline angle;
- multi-view 3D agreement;
- optional local image/backbone feature.

The important distinction is that lack of support from another view does not automatically mean the point is wrong. A point may be valid but hidden by occlusion. The supervised head learns to separate:

```text
not supported because occluded
vs
not supported because geometrically wrong
```

Training labels can be generated from ground-truth geometry. For a predicted point `X_pred`, compute its distance to the nearest GT surface:

```text
d = distance(X_pred, nearest_GT_surface)
```

Then:

```text
y_keep = 1 if d < tau_good
y_keep = 0 if d > tau_bad
```

Visibility labels can be generated by projecting the point into each view and comparing predicted depth with GT rendered depth:

```text
abs(z_pred - z_GT) <= tau_z  -> visible / consistent
z_pred > z_GT + tau_z        -> occluded
z_pred < z_GT - tau_z        -> floating or wrong geometry
```

Recommended loss:

```text
L_oarh =
    BCE(y_keep, r)
  + lambda_1 BCE(y_visible, v)
  + lambda_2 SmoothL1(depth_residual)
```

Focal loss can be used if positive and negative point labels are imbalanced.

## Repeated-Structure Disambiguation Head

Repeated objects should not be removed simply because they look similar. Chairs, windows, cabinets, and floor patterns may be repeated but still geometrically correct. The correct objective is to remove false correspondences inside repeated regions.

We therefore train a match validity head:

```text
m(i, j) in [0, 1]
```

where `m(i, j)` is the probability that a candidate match between pixel `i` in one view and pixel `j` in another view is valid.

MASt3R is a good feature/matching source for this module because it provides dense local features and reciprocal matching. Candidate match features include:

- reciprocal match flag;
- feature distance;
- nearest/second-nearest descriptor margin;
- reprojection error;
- 3D disagreement between pointmaps;
- cycle consistency error;
- optional semantic or edge cue.

Ground-truth match labels are generated from 2D-3D mappings. A match is positive if both pixels map to the same surface or nearby 3D location, and negative if they are visually similar but map to far-apart 3D surfaces.

Recommended loss:

```text
L_match = BCE(y_match, m)
```

An optional contrastive or triplet term can strengthen repeated-structure training:

```text
positive = same GT surface or nearby 3D point
negative = visually similar repeated region but different GT surface
```

## Training Strategy

The recommended training schedule is staged:

| Stage | Action | Purpose |
| --- | --- | --- |
| A | Freeze MV-DUSt3R+, train OARH/RSDH | Fast, stable, debuggable |
| B | Freeze encoder, unfreeze confidence head and last decoder blocks | Calibrate confidence and pointmaps |
| C | Wider fine-tuning | Only if Stage A/B improve validation |
| D | Train from scratch | Not recommended |

For partial fine-tuning:

```text
L_total =
    L_pointmap
  + lambda_1 L_conf_calibration
  + lambda_2 L_visibility
  + lambda_3 L_match_disambiguation
  + lambda_4 L_multiview_consistency_visible_only
```

The most important constraint is:

```text
do not enforce multi-view consistency through occluded views
```

This directly addresses the failure mode observed in the heuristic occlusion filter.

## Evaluation Plan

Use scene-level splits:

```text
train: 60%
val:   20%
test:  20%
```

If the dataset subset is small:

```text
train: 6 scenes
val:   2 scenes
test:  2 scenes
```

The test scenes must never appear in training. Thresholds and checkpoints must be selected on validation scenes only, then frozen for final test.

## Expected Contribution

If successful, the learned extension turns the project into a stronger contribution:

| Limitation | Proposed solution |
| --- | --- |
| Far-reference views | visibility-aware sparse-view selection |
| Severe occlusion | supervised occlusion-aware reliability learning |
| Repeated structures | learned match disambiguation with reciprocal and cycle consistency |

This is a cleaner path than continuing to tune heuristic filters, because it uses geometry supervision to learn when a point or match is actually reliable.

## Risks

- Ground-truth label generation must be correct; poor labels will dominate the training signal.
- MASt3R matching increases preprocessing cost.
- OARH/RSDH may improve precision while reducing completeness, so recall must be reported.
- Scene-level split is mandatory; otherwise the learned heads may overfit scene geometry.
- Partial fine-tuning may overfit if the train split is too small.
